## 面板限高（1000×620 小窗口）

| 字段 | 值 |
| --- | --- |
| panel rect | `{ x: 527, y: 8, w: 264, h: 581 }` |
| `scrollHeight` / `clientHeight` | **720 / 581** |
| `overflow-y` | `auto` |
| 视口 | 1000×620 |

面板顶部仍在视口内（`y=8`），底部 `589 < 620`；内容超高时在面板内滚动，
标题与「刷新」不会被裁掉。默认 1002px 窗口下 `scrollHeight === clientHeight`
（700），不出现无意义的滚动条。

## 配置切换守卫（v0.1.6 主线修复）

`v016-config-switch` 变体通过 React fiber 找到插件的 `service.settings`，调用与
设置行相同的 `update({ format: 'bonus' })`，再点面板「刷新」：

```json
{
  "switched": { "ok": true, "settings": { "format": "bonus" } },
  "beforeLevel": "warn",
  "afterLevel": "low",
  "afterMatches": 0,
  "afterOwnLevel": null
}
```

档位确实从 `warn` 跳到 `low`（证明切换生效），但**没有出现提醒卡**。旧实现会在
这里弹「余额不足：当前 ¥0.00」；v0.1.6 用 `configKey` 把「配置变化」与「真实掉档」
分开。配置稳定后的真实掉档仍由单测锁定（`advanceAlert` 用例）。

## 充值对账

真实 GUI 的种子历史含一次充值（`out/v016-pill.json` 的 `seed` 记录：
36 个采样点、金额先降后升再降）。面板的「今日/本周/近 7 天」都有正数，
没有被充值归零。精确的「逐段下降」算术由单测覆盖（`spentFromSamples` /
`spendInDay` / `spendInWeek` / `spendInWindow` 用例）。

## 没有跑的部分（诚实记录）

- **`v14-runout` 变体没有跑**：它要求账号在两次读数之间真实消耗（间隔 ≥30 秒、
  余额至少掉 0.01），本轮余额在 ¥4.5 附近、空闲时段消耗很慢；这条属于 v1.4 的
  耗尽预估，不是 v0.1.6 的改动。`data-balance-runout` 的既有单测仍全绿。
- 验证台的 `v14-balance-alert` 旧变体（切口径 → 弹卡）在 v0.1.6 下**应当失败**：
  它验证的正是本版修掉的假提醒。新的 `v016-config-switch` 变体验证相反的行为
  （切口径不弹卡），并已通过；历史 `variants-v14.json` 保留作 v1.4 证据，不再用于
  当前版本的验收。

## 验证台自身修掉的两处假设

1. **跨天文案的解析**：`countdownToMs` / `displayGranularityMs` 原来只认
   `^\d+ 天$`。v0.1.6 的倒计时变成「天 + 小时 + 分钟」后，解析漏掉「天」，
   报出 4 条假失败。现在按出现的最小单位计算容差、把天/小时/分钟相加。
2. **余额提醒选择器**：旧 `BALANCE_ALERT_INSPECT` 会把面板里的「余额偏低，
   建议尽快充值」也当成提醒卡（因为它含「充值」）。现在只认带「当前金额」的
   提醒文案，并排除面板与徽章子树。
