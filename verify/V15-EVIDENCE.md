## 修掉的一处验证台缺陷

本次实测一开始报出 **10 条失败**，全部是同两条断言的重复：

```
FAIL 倒计时行的 {duration} 与边界自洽（±2 分钟）
FAIL 空闲区间：时长 = end - start（±90 分钟）
```

面板当时显示「距下一个高峰 **1 天**」「本段空闲…（共 **3 天**）」，而真实剩余是
1 天 21 小时 30 分、真实跨度是 3 天 15 小时 —— **`formatCountdown` / `formatDuration`
在「天」这一档只给整数天**（前者向下取整，后者四舍五入）。拿 ±2 分钟去比一天的量化
误差，是验证台的假设错了，不是插件算错了。

已改为**容差 = 展示粒度**：

```js
function displayGranularityMs (text) {
  if (/^\d+ 天$/.test(text)) return 86400000
  if (/\d+ 小时/.test(text)) return 3600000
  if (/\d+ 分钟/.test(text)) return 60000
  if (/^\d+ 秒$/.test(text)) return 1000
  return null
}
```

修好后 170 条断言全部通过。这个修法与 v1.4 修「省一半」的精度假设（`<0.01` 下溢）
是同一类：**断言必须按界面的显示精度比较，而不是按内部数值**。
